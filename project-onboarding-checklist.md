# Project Onboarding Checklist

## 1. Register project

- [ ] Project name:
- [ ] Classification: cbqa / nexora / freelance / personal / sandbox
- [ ] Local path:
- [ ] Repository URL:
- [ ] Default branch:
- [ ] Development branch:
- [ ] Owner or responsible person:

## 2. Identify technology

- [ ] Frontend framework:
- [ ] Backend framework:
- [ ] Database:
- [ ] Runtime:
- [ ] Package manager:
- [ ] Test framework:
- [ ] Build command:
- [ ] Lint command:
- [ ] Test command:

## 3. Add project AGENTS.md

- [ ] Project overview
- [ ] Architecture boundaries
- [ ] Important business rules
- [ ] Safe commands
- [ ] Dangerous commands
- [ ] Local setup
- [ ] Test and build commands
- [ ] Definition of done

## 4. Access and security

- [ ] No production credentials in local files
- [ ] `.env.example` exists
- [ ] Secrets are ignored by Git
- [ ] Database access is local or read-only staging
- [ ] Agent permission is Ask before changes
- [ ] Production deployment is disabled for agents

## 5. First validation task

Use a low-risk task such as:

> Inspect this repository. Do not modify files. Identify the stack, architecture, setup commands, test commands, top five technical risks, and three safe starter tasks. Return a report in Markdown.

- [ ] Report reviewed
- [ ] Agent understood the repository
- [ ] No unintended changes
- [ ] Repository is ready for implementation tasks

## 6. Add agent roles

- [ ] Lead / Codex
- [ ] Frontend
- [ ] Backend
- [ ] QA
- [ ] Code Review
- [ ] DevOps
- [ ] Documentation

## 7. Task closure

- [ ] Acceptance criteria checked
- [ ] Tests executed
- [ ] Diff reviewed
- [ ] QA result recorded
- [ ] Code review completed
- [ ] Human approval received
- [ ] Merge or deployment completed manually
- [ ] Documentation/changelog updated
